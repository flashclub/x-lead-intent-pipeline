我和 Jev 打了一架：5 万参数小模型 vs 商业 System One API

我训练了一个 5 万参数的小模型，在 X 上判断"这条帖子有没有购买意向"（训练过程见前一篇）。调研行业时发现，前 OpenAI 研究者 Diogo Almeida 创立的 TypeSafe AI 把同一个范式做成了商业产品——System One 模型 Jev。

同一个赛道，那就直接摆擂台：用它家官方 API，和我们的小头，在同一批数据上正面对比。这篇文章把方法、过程、数据和结论全部摊开，每一行都可复核。

摆擂台之前：先把 Jev 的门敲开

对比的第一步是接入，这一步就花了一番功夫——Jev 的接口协议没有任何公开文档，我是这样摸出来的：

1. 从生态找协议。 Jev 用的接口叫 System One 协议。多家网关（OpenRouter、Vercel AI Gateway）和本地推理引擎（llama.cpp）都在兼容同一套格式，本地 AI 工具链的源码里就有这套协议的完整实现——直接读源码，比猜快得多。

2. 逐字段试错。 第一版请求立刻被 API 纠错（返回的是协议校验信息而非 401，说明端点和密钥都对）：判定问题必须带 criteria，criteria 必须是对象且要区分 true / false 两种情形的判定标准。按它要求的形状重发，通了。

3. 模型名从官方列表拿。 jev-1 不存在，GET /v1/models 列出的是 jev-latest 和 jev-preview，实际服务版本是 jev-1.14.0。

4. 极性校准。 判断接口返回的数字到底是不是"购买意向概率"，光看文档没用——拿两条极端帖子实测：强意向帖（"willing to pay"）返回 0.93，纯噪音帖（"just watched the new Dune movie"）返回 0.08。方向确认无误，才敢开跑。

这四步做完，Jev 在我这边就是一个"输入帖子、输出 0-1 分数"的标准判分器了——和我们的小头站在了同一条起跑线上。

测试方法

  • 数据：7,866 条标注数据按训练时同款切分还原出的 held-out test 集（模型从未见过），确定性分层抽样 300 条：96 条意向 / 204 条噪音
  • 参考基准：teacher 标签（Gemini 2.5 Flash）；teacher 对人工判断的一致率约 90%
  • 判定阈值：0.5，双方一致
  • Jev 侧：官方 API，模型 jev-latest（实际 jev-1.14.0），判定标准写死在请求 criteria 里，单条逐请求
  • 我方：同一个 300 条、同一个 0.5 阈值，本地 MacBook CPU 推理
  • 延迟口径：Jev 计含网络往返；我方为服务端逐条计时

测试过程

每个模型对同一批 300 条逐一打分，600 次判断全程落盘：每条的双方分数、判定、对错、耗时都存成 CSV，可逐条复核。Jev 每条含网络往返约 0.87 秒，我们的头每条约 0.03 秒——整个对比 Jev 侧跑了约 5 分钟，我方 10 秒。

测试结论

| 模型 | 一致率 | ROC-AUC | 精确率 | 召回率 | F1 | 单条延迟 |

| --- | --- | --- | --- | --- | --- | --- |

| 我们的 49k 头 | 0.92 | 0.952 | 0.875 | 0.875 | 0.875 | 0.033s |

| Jev（jev-latest） | 0.80 | 0.860 | 0.891 | 0.427 | 0.576 | 0.873s |

两个模型都做到了"前 5 条全是精准线索"（precision@5 = 1.00），但拆开看是两种完全不同的性格。

发现一：Jev 是极端保守型

它很少误报（精确率 0.891），代价是 55 条真正的意向帖被它漏掉了——召回率只有 0.427，一半以上的买家从它眼皮底下溜走。看几条它放过的帖子：

"i wish there was an app where we could talk about this" —— Jev 0.20（我们 1.00）
"Is there an app to find the nearest batting cage?" —— Jev 0.27（我们 0.99）
"To anyone who has an uterus i have a question is there an app that lets you track…" —— Jev 0.45（我们 1.00）

发现二：lead mining 场景，召回比精确值钱

漏掉一个买家的代价远大于多看一条噪音——多看一条只是 0.03 秒，漏掉一个就是丢一个客户。所以召回端的差距（0.875 对 0.427）比总体一致率更能说明问题。70 条双方判定不一致的样本，我们在报告附录里逐条列出，谁对谁错一目了然。

发现三：领域专用蒸馏赢得了专用任务

Jev 是通用判断模型，要兼顾千万种问题类型；我们的头只用 7,866 条数据学一件事。专用任务 + 领域数据 + 蒸馏，5 万参数打赢了商业大厂的产品——这不是小模型奇迹，而是"领域蒸馏"这条路线的常规收益。

诚实口径与边界

  • 以上全部是模型与 teacher 的一致率，teacher 对人工判断的一致率约 90%——双方在同一基准下对比，结论成立；但没人达到过 ground truth
  • Jev 两次运行的总体一致率在 0.80-0.81 之间小幅波动（其 API 非确定性），我们取了后一次的完整数据
  • 对比仅覆盖"购买意向"这一个判定类型，不构成对 Jev 其他能力（多问题类型、图片输入等）的评价

什么时候选谁

| 场景 | 建议 |

| --- | --- |

| 通用类型化判断、多领域、不想自己养数据 | Jev 这类商业 API——接入快，判断稳 |

| 单一领域、有数据、高QPS、成本敏感、要私有化 | 自建蒸馏小模型——一次蒸馏，之后每次判断几乎免费 |
